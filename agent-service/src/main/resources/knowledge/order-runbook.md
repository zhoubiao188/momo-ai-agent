# 订单中心运行手册

## 订单状态机

订单状态流转：`CREATED（待支付）` → `PAID（已支付）` → `SHIPPED（已发货）` → `COMPLETED（已完成）`，任意已支付状态可进入 `REFUNDING（退款中）` → `REFUNDED（已退款）`；超时未支付由定时任务置为 `CLOSED`。

禁止的流转：`CREATED` 不能直接退款；`CLOSED` 不能重新支付，只能重新下单。

## 订单查不到怎么办

1. 确认订单号格式是否为 `MO` + 日期 + 序号，共 13 位；
2. 用 `order_lookup` 查一次，确认返回 4040（订单不存在）还是 4090（状态不允许）；
3. 若订单号正确但仍查不到，检查是否走了分库分表：订单号后三位是分片键，跨分片查询需要走 ES 索引；
4. 以上都正常，让用户提供支付流水号，到支付中心反查 `out_trade_no`。

## 退款流程

1. 校验订单状态属于 `PAID` / `SHIPPED` / `COMPLETED`；
2. 调用支付中心 `refund` 接口，传入原 `traceId` 以便对账；
3. 订单先置为 `REFUNDING`，收到支付中心异步回调后置为 `REFUNDED`；
4. 超过 30 分钟未收到回调，由对账任务补偿，人工不要重复发起退款。

## 支付回调超时

现象：日志出现 `payment timeout after 3000ms, retrying`，订单停留在 `CREATED`。
处置：
1. 先看 `payment-service` 的错误率与 P99；
2. 确认渠道侧（支付宝/微信）是否有公告；
3. 打开支付网关的重试队列，重试次数上限 3 次，超过后进入人工对账；
4. 不要手工改订单状态，等回调或对账任务收敛。
