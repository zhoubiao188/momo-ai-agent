# 库存与下游依赖运行手册

## 库存锁定失败

现象：日志 `stock locked failed: sku=SKU-77 insufficient`，订单创建失败。
处置：
1. 确认是真实库存不足还是缓存与 DB 不一致（对比 Redis 与 DB 的可用库存）；
2. 缓存不一致时执行 `stock-service` 的 `syncCache` 运维接口，禁止直接改 DB；
3. 大促期间允许「超卖保护」降级：锁定失败直接返回可购买数量，由前端引导；
4. 连续 5 分钟失败率 > 5% 触发值班升级。

## 下游 504 超时

现象：`downstream call /stock/lock returns 504`。
处置：
1. 用 TraceId 在链路追踪里定位是网络、连接池还是下游慢查询；
2. 检查 `stock-service` 线程池与 DB 连接池是否打满（`hikari_active` 指标）；
3. 临时方案：将 `lockStock` 的超时从 3s 调到 1s 并开启熔断，快速失败优于线程堆积；
4. 恢复后确认熔断器半开状态，避免长时间全量放行造成二次雪崩。

## 值班升级路径

- P3：自助处理，记录到值班日志；
- P2：15 分钟未恢复，升级到当班组长；
- P1：5 分钟未恢复，拉起电话会议并同步业务方；
- 所有 P1/P2 必须在 24 小时内产出复盘，包含时间线、根因、改进项。
